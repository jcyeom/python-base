# 개정 이력 및 근거

초고 대비 [`00-paper-revised.md`](00-paper-revised.md)에서 변경된 사항과 그 근거를 정리한다.
각 항목은 [`02-design.md`](02-design.md)의 대응 절과 연결된다.

## A. 반드시 고쳐야 했던 사항 (논지 결함)

| # | 원문 위치 | 문제 | 개정 내용 | 설계 대응 |
|---|-----------|------|-----------|-----------|
| A1 | 3.1 "확률적 라벨러는 동일 seed·동일 프롬프트 하에서 준결정적으로 동일 라벨을 재생성" | 2.2에서 인용한 [7]의 run-to-run 재현성 문제와 정면 충돌. 상용 LLM API는 seed 고정으로도 재현을 보장하지 않으며(배치 수치 비결정성, alias 뒤 모델 갱신), 심사에서 반박 가능 | 목표를 재현(reproduce)에서 **재생(replay)** 으로 변경. 원시 응답을 Bronze에 보존하고 날짜 고정 모델 ID를 강제 | §3.3, §5.2 |
| A2 | 3.3 "합의 판정에는 Cohen's κ, 다수결, 신뢰도 가중 평균 등의 정책을 적용" | 범주 오류. κ는 데이터셋 수준의 우연 보정 일치도 지표이지 표본 단위 판정 함수가 아님. 또한 Cohen's κ는 평가자 2인 전용인데 본 설계는 3인 이상 + 기권(결측) 상황 | 합의 정책(다수결/가중투표/생성모델)과 모니터링 지표(Krippendorff's α)를 분리 서술 | §3.5, §7.4 |
| A3 | 알고리즘 1, `confidence_gap(L1) > θ` | rule(고정 1.0), LLM(자기 보고, 과신 경향), human(주관 점수)의 신뢰도를 동일 축에서 비교 가능하다고 전제. 성립하지 않음 | 앵커 기반 라벨러별 단조 보정 함수 도입. `confidence_raw`와 보정된 `confidence`를 분리 저장. 부트스트랩 경로 명시 | §3.5(b), §8 |
| A4 | 알고리즘 1, `L2(x) ← NULL` | 불일치 표본만 학습셋에서 체계적으로 빠져 선택 편향 발생. 모델이 경계 사례에서 과신하게 됨 | 최선 추정값 + 소프트 분포를 기록하고 `pending_review` 플래그 부여. 학습 포함 여부는 매니페스트 필터로 명시 선언 | §3.5(d), §11 |
| A5 | 3.2 L3 정의, 3.4 앵커 재채점 | L3는 정의상 불일치 표본에서만 생성되므로 "절대 정확도" 기준으로 쓸 수 없음(모집단 미대표). 폐루프에서 자기강화 편향 누적 | 검수 예산의 비율 ρ를 무작위 표본에 강제 배정하는 **앵커 집합** 도입 | §3.6, §9 |
| A6 | 3.2 L3 정의 | L3가 학습 라벨·라벨러 평가 기준·드리프트 앵커 3역할을 겸해 누수 발생. 라벨러 성능이 낙관 추정됨 | `l3_purpose ∈ {train, eval_holdout}` 사전 분할. holdout은 Fusion Engine에 비노출 | §3.6, §4.5 |
| A7 | 3.4 드리프트 감지 | PSI/KL 단독으로는 라벨러 드리프트와 입력 드리프트를 식별 불가. 재난 안전 도메인은 입력 분포 변동이 정상 | 두 신호 조합 식별 규칙을 표 3으로 명시 | §3.7, §10 |
| A8 | 표 1, `agreement` 필드 | "다중 라벨러 raw 결과의 구조화 기록"은 개별 L1이 알 수 없는 정보. L1에 두면 순환 의존 + append-only 위배(사후 UPDATE 필요) | L2 스키마로 이동. L1은 불변 레코드로 확정 | §3.2, §4.3 |

## B. 구현을 막던 스키마 누락

| # | 누락 | 영향 | 개정 |
|---|------|------|------|
| B1 | `sample_id` | feature와 조인할 키가 없어 테이블 생성 자체가 불가 | 표 2 식별 그룹에 추가, PK 정의 |
| B2 | `label_task` | 한 샘플에 복수 태스크가 붙는 순간 스키마 붕괴 | 추가 |
| B3 | `target_ref` | 라벨 단위(문서/스팬/bbox)가 다르면 합의가 정의되지 않음 | 추가 |
| B4 | `is_abstain` | Snorkel 계열의 핵심인 기권을 `value` NULL로 뭉개면 합의가 왜곡 | 추가, 알고리즘 1행에 명시 처리 |
| B5 | `ontology_ver` | 클래스 체계 변경 시 구 라벨의 재해석 정책 부재 | 추가, §6에 마이그레이션 규칙 |
| B6 | `run_id` | append-only 테이블에서 재실행분 구분 및 멱등성 키 부재 | 추가, PK 포함 |
| B7 | `value` 단일 컬럼 | "분류: 클래스, 회귀: 실수"를 한 컬럼에 담을 수 없음 | `value_type` 판별자 + 타입별 컬럼 분리 |
| B8 | `cost` / `latency_ms` / `token_usage` | 논문이 주장하는 "검수 비용 절감률"의 원천 데이터. 사후 복원 불가 | 추가 |
| B9 | LLM 메타 세분화 | `method_ver` 하나로는 프롬프트·샘플링 파라미터·검색 컨텍스트 변경을 구분 불가 | `prompt_hash`, `params_hash`, `retrieval_ctx_hash` 분리 |
| B10 | `feature_snapshot_id` | 해시만으로는 입력 복원 불가 | 추가, time travel 보존 설정과 함께 §5.3 |
| B11 | L2 재현 메타 | `fusion_policy_ver`, `theta`, `input_l1_run_ids` 부재로 L2에서 계보가 끊김 | L2 스키마에 추가 |

## C. 구조적 보강

| # | 내용 | 근거 |
|---|------|------|
| C1 | **일급 객체의 조작적 정의(표 1)** 신설 | "무엇이 일급인가"에 답하지 못하면 기여가 모호. 7개 조건으로 조작화하고 기존 도구 대비 차별점(C4 계보, C7 표준 질의)을 특정 |
| C2 | **4계층 매핑** (L0 Bronze 원시 응답 추가) | 초고는 라벨러 원시 출력을 Silver에 배치했으나 Silver의 통상 정의(정제·정합 계층)와 충돌. 원시 응답을 Bronze로 분리하면 재생(A1) 경로도 함께 확보 |
| C3 | **라벨러 상관 보정** 추가 | 동일 기반 모델을 쓰는 LLM 라벨러 복수 운용 시 다수결이 중복 투표를 허용. Snorkel을 인용하면서 fusion은 단순 다수결로 후퇴하면 차별점 방어 불가 |
| C4 | **데이터셋 매니페스트** 신설(3.8) | "학습 데이터셋"을 가리키는 식별자가 없어 모델→데이터→라벨→라벨러→feature 계보가 끊김. C4 조건 충족의 핵심 |
| C5 | **평가 계획(4장)** 신설 | 기존 계획(합의도·비용 절감)은 어떤 다중 라벨러 시스템이든 보일 수 있는 숫자. 고유 주장인 "L1 영구 보존"의 효용을 직접 측정하는 축 2를 추가 |
| C6 | 정규화 해시 규격 명문화 | 직렬화 방식이 흔들리면 같은 입력이 다른 해시를 생성. 재현성 주장의 전제 |
